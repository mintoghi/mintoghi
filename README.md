# 교복 학교주관구매 길라잡이 — 웹앱 연습판

기존 자료(`개발문서/`, `_workspace/05_web/`)는 **읽기만** 하고, 이 폴더에 웹앱 화면을 새로 만든 연습판입니다.

## 실행

`index.html`을 더블클릭합니다. 서버, 빌드, 인터넷 연결이 필요 없습니다.

- 원본 웹앱(Vite)은 `file://`로 열면 모듈 스크립트가 CORS에 막혀 실행되지 않습니다(`웹앱_task.md` WP-03-13 참고). 연습판은 이 문제를 피하려고 일반 `<script>`만 씁니다.
- 원본 JSON이 바뀌면 이 폴더에서 `node tools/build-data.js`를 다시 실행해 `data/data.js`를 갱신합니다.

| `tools/e2e.js` | 헤드리스 Chrome 동작 검증 34항목 |

## 검증 (2026-10-08)

`node tools/e2e.js "<index.html 절대경로>" <스크린샷 폴더>` 실행 결과는 **34/34 통과**이고, 2회 연속 같은 결과가 나왔습니다.

- 8개 화면이 렌더링되고 콘솔 오류는 0건입니다.
- 입력하면 배지·탭 개수·자동계산(10 × 50,000 = 500,000원)이 바로 갱신됩니다.
- 새로고침해도 세션 값이 유지됩니다.
- 서식함 필터 결과: 계약 단계 3종, F-019 검색 1종.
- 미리보기에 학교명이 반영되고, 포커스가 모달 안에 머물며 Esc로 닫힙니다.
- F-029는 개인정보 보호 문서라 빈 양식으로 표시됩니다.
- 400px 폭 4개 화면에서 가로 넘침이 없습니다.

## 원본 설계와 다른 점 (의도적으로 범위에서 뺀 것)

- **HWPX 작성**: 버튼을 노출하지 않습니다. 원본 결정(ADR-001)에 따라 HWPX는 Excel 로컬 경로에서 만듭니다.
- **업무자료.xlsx 업로드/다운로드, PDF·HWPX 일괄 ZIP**: 외부 라이브러리가 필요해 연습판에서는 JSON 백업으로 대신했습니다.
- **미리보기 레이아웃**: 원본 HWPX 서식을 재현하지 않습니다. 입력값이 어떤 칸에 들어가는지 확인하는 표 형식입니다(화면에 워터마크로 표시).
- **학교 검색(790개 학교 DB)**: 원본 데이터가 이 폴더에 없어 구현하지 않았습니다.

## 남은 병목

1. **모든 단계(20개)의 체크리스트가 1항목입니다.** `workflows.json`의 `checklistItems`가 업무설명 문장을 그대로 옮긴 1개뿐이라, "해야 할 일 3개"처럼 나뉜 시안(screen-3)과 다릅니다. 매뉴얼에서 단계별 할 일을 나눠 데이터에 넣어야 화면이 시안대로 됩니다.
2. **담당구분(학교/업체/공동)은 근거가 약합니다.** 원본 Excel에 없는 값을 업무설명의 주어에서 추정한 것이라, 화면에 "매뉴얼 확인 필요" 툴팁만 달아 두었습니다.
3. **입찰 계열 공통 필수서식은 서술형입니다.** CM-03·04는 `commonRequiredForms`가 `null`이고 원문 문장만 있어, 카드에 문장을 그대로 표시합니다.
4. **WCAG 대비를 실측하지 않았습니다.** 색 대비 자동 검사와 스크린리더 실사용 점검은 아직 하지 않았습니다.
